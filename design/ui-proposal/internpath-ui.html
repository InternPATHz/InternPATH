โครงหน้า

  • เปลี่ยนจากหน้าเดียวกล่องซ้อนกล่อง เป็นแถบเต็มความกว้างสลับสีขาว/เทา/ดำ ใช้การเปลี่ยนสีแทนเส้นแบ่ง
  • ลำดับ: Hero + ค้นหา → หมวดงาน (ดำ) → ประกาศล่าสุด (เทาอ่อน) → ป้ายความน่าเชื่อถือ (ดำ) → สามขั้นตอน → Footer
  • ตัดหัวข้อ h1 ซ้ำซ้อนด้านบน Hero ออก ให้ Hero เป็นหัวข้อเดียวของหน้า

คอมโพเนนต์

  • เมนูบนเป็นแถบดำสูง 44px ตามแบบ global-nav ปุ่มเข้าสู่ระบบเป็น button-dark-utility
  • ช่องค้นหาและปุ่มหลักเป็นทรงแคปซูล (search-input, button-primary) เพิ่มชิปคำค้นยอดนิยม
  • การ์ดงานเป็น store-utility-card: ขาว ขอบ 1px มุม 18px ไม่มีเงา
  • เงามีที่เดียวคือการ์ดตัวอย่างใน Hero ซึ่งทำหน้าที่เป็น "ภาพสินค้า"

UX ที่ปรับ

  • ป้าย Verified / University Partner ใช้พื้นเทาและเครื่องหมายถูกสีเขียว ส่วน Featured เป็นป้ายเส้นขอบสีจาง เพื่อให้เห็นว่าเป็นคนละความหมาย
  • ย้ายคำอธิบายป้ายจากกล่องข้อความเล็กท้ายหน้า มาเป็นแถบเต็มที่อ่านได้ทันที
  • เพิ่มจำนวนประกาศต่อหมวด (ต้องมี API นับจำนวน) และส่วน "สามขั้นตอน" เพื่ออธิบายระบบให้ผู้ใช้ใหม่

ค้นหางาน: สิ่งที่เปลี่ยน

โครงหน้า

  • เพิ่มแถบย่อยโปร่งแสง (sub-nav-frosted) ติดใต้เมนูหลัก บอกว่าอยู่หน้าไหน
  • แบ่งเป็นสามชั้นตามสีพื้น: หัวค้นหา (เทาอ่อน) → ตัวกรอง (ขาว) → ผลลัพธ์ (เทาอ่อน) ไม่ต้องใช้กรอบ
  • ตัวอย่างนี้แสดงตอนนักศึกษาล็อกอินแล้ว เมนูตามบทบาทอยู่ในแถบดำ มีกระดิ่งแจ้งเตือนกับรูปโปรไฟล์

ตัวกรอง

  • เปลี่ยน dropdown สายงานและรูปแบบการทำงานเป็นชิปกดเลือกได้ทันที (configurator-option-chip) ตัวที่เลือกมีขอบน้ำเงิน 2px
  • checkbox "มีค่าตอบแทน" กลายเป็นชิปแบบเดียวกัน
  • แสดงตัวกรองที่ใช้อยู่เป็นป้ายมีปุ่ม × เอาออกทีละตัว และมี "ล้างทั้งหมด"
  • บนมือถือ ชิปเลื่อนแนวนอนได้ และย้าย "เรียงตาม" มาอยู่ในแถวชิป

สาขาของผู้ใช้

  • เดิมเป็นช่องกรอก "สาขาของคุณ" ที่ต้องพิมพ์ให้ตรง ตอนนี้แสดงสาขาจากโปรไฟล์เป็นข้อความหนึ่งบรรทัด พร้อมลิงก์ "เปลี่ยนสาขา"
  • คำเตือนสาขาไม่ตรงย้ายจากป้ายสีเหลืองด้านบนการ์ด มาเป็นกล่องข้อความในการ์ด บอกว่าประกาศรับสาขาอะไร และย้ำว่ายังสมัครได้

การ์ดผลลัพธ์

  • จำนวนตำแหน่งที่เหลือแสดงเป็นแถบ เห็นได้เร็วกว่าตัวเลขบรรทัดเล็ก
  • ประกาศที่ปิดรับภายใน 7 วันแสดงเป็น "อีก N วัน" สีส้มแทนวันที่
  • ปุ่ม "ดูรายละเอียด" เป็นลิงก์ข้อความสีน้ำเงิน ไม่ใช่ปุ่มพื้นสี ตามหลักที่ปุ่มทึบมีแค่ปุ่มหลักของหน้า
  • ปุ่มบันทึกประกาศและจำนวนต่อหมวดเป็นฟีเจอร์ใหม่ ต้องมี API รองรับ

1ข้อมูลที่เราเก็บ

  • ข้อมูลบัญชี: อีเมล ชื่อ-นามสกุล เบอร์โทร (ถ้ามี) และรหัสผ่าน (เก็บเป็นค่าแฮช ไม่เก็บรหัสผ่านจริง)
  • นักศึกษา: รหัสนักศึกษา สาขา ชั้นปี สถาบัน เรซูเม่และโปรไฟล์ ใบสมัครและสถานะ ผลประเมินการฝึกงาน รีวิวบริษัท และรายงานปัญหาระหว่างฝึกงาน
  • อาจารย์ที่ปรึกษา: ภาควิชา และการผูกกับนักศึกษา
  • บริษัทและ HR: ชื่อและเลขทะเบียนนิติบุคคล เว็บไซต์ เบอร์โทรบริษัท เอกสารยืนยันบริษัท และประกาศงาน
  • บันทึกการทำงานของระบบ: ประวัติการเปลี่ยนสถานะ และบันทึกการกระทำของผู้ดูแลระบบ ซึ่งไม่มีเนื้อหาข้อความส่วนตัวของคุณ

เข้าสู่ระบบ: สิ่งที่เปลี่ยน

โครงหน้า

  • เปลี่ยนจากการ์ดมีขอบและเงาบนพื้นเทา เป็นพื้นขาวล้วนแบบหน้า Apple Account ไอคอนแอปวางกลางพร้อมเงาเดียวของระบบ
  • คงแถบดำด้านบนไว้ ผู้ใช้กลับไปหน้าค้นหางานได้โดยไม่ต้องเข้าสู่ระบบ

ฟอร์ม

  • ช่องกรอกสูง 56px ป้ายชื่ออยู่ในช่อง (แบบ Apple) มุม 11px
  • เพิ่มปุ่มแสดง/ซ่อนรหัสผ่าน
  • ปุ่มหลักทรงแคปซูลเต็มความกว้าง
  • ลิงก์ "ลืมรหัสผ่าน / บัญชีถูกล็อก" อยู่กลางใต้ปุ่ม สีน้ำเงินชัดเจน เดิมเป็นสีจาง

ข้อผิดพลาด

  • ข้อผิดพลาดแสดงเป็นแถบสีแดงอ่อนเหนือปุ่ม พร้อมทางแก้ไขในประโยคเดียว
  • กรณีบัญชีถูกล็อก แถบบอกเหตุและลิงก์ไปหน้าปลดล็อกโดยตรง
  • กรณียังไม่ยืนยันอีเมล ลิงก์ไปหน้าส่งอีเมลยืนยันซ้ำ

ต้องตรวจ

  • ข้อความผิดพลาดตอนนี้ใช้ cause.message จาก API ตรง ๆ ถ้าจะแยกแถบตามกรณี (ล็อก / ยังไม่ยืนยัน) ต้องอ่าน code ของ error แทน

  • ปุ่มเลือกบทบาทเปลี่ยนเป็นการ์ดมีไอคอนและคำอธิบายสั้น ๆ ว่าบัญชีนี้ใช้ทำอะไร ตัวที่เลือกมีขอบน้ำเงิน 2px (configurator-option-chip-selected)
  • บนมือถือการ์ดเรียงเป็นแนวตั้ง ไอคอนอยู่ซ้าย

ฟอร์ม

  • แบ่งฟอร์มเป็นกลุ่ม "ข้อมูลบัญชี / ข้อมูลการศึกษา / รหัสผ่าน" ไม่ต้องไล่อ่าน 8 ช่องติดกัน
  • สาขากับชั้นปีอยู่แถวเดียวกัน ชั้นปีเป็นตัวเลือก 1–6 แทนช่องพิมพ์ตัวเลข
  • คำอธิบายใต้ช่องอีเมลบอกเหตุผลว่าทำไมต้องเป็น .ac.th
  • ตรวจรหัสผ่านทันทีที่พิมพ์: ความยาว 12 ตัว และยืนยันรหัสตรงกัน ไม่ต้องรอกดส่ง

ข้อความตามบทบาท

  • อาจารย์: บอกตั้งแต่ก่อนกดสมัครว่าต้องรอผู้ดูแลระบบอนุมัติ เดิมบอกหลังสมัครเสร็จ
  • บริษัท: แยกกลุ่ม "ข้อมูลบริษัท" ไว้บนสุด เลขทะเบียนนิติบุคคลบอกรูปแบบ 13 หลัก

ต้องตรวจ

  • แถบความแข็งแรงของรหัสผ่านเป็นการแสดงผลในหน้าเว็บเท่านั้น เงื่อนไขจริงยังเป็น 12 ตัวอักษรขึ้นไปตามเดิม
  • ถ้าชั้นปีมีมากกว่า 6 (เดิมรับ 1–10) ต้องปรับตัวเลือก

โครงหน้า

  • การกระทำหลักอยู่ใต้ชื่อประกาศทันที และเปลี่ยนตามสถานะ เช่น ถูกตีกลับ = "แก้ไขแล้วส่งตรวจใหม่" + "อุทธรณ์"
  • เพิ่มลิงก์ "ดูแบบที่นักศึกษาเห็น" เปิดหน้ารายละเอียดงานแบบสาธารณะ
  • ประวัติของประกาศเป็นเส้นเวลาด้านขวา เหมือนหน้ารายละเอียดใบสมัคร

ผลการตรวจสอบ

  • ระดับความเสี่ยงแสดงเป็นแถบสามขีด พร้อมคำ (ต่ำ / ปานกลาง / สูง)
  • เหตุผลจากผู้ดูแลระบบอยู่ในกล่องแดงอ่อน และไฮไลต์คำที่เป็นปัญหาในเนื้อหาประกาศด้วยสีเดียวกับคิว Admin

ต้องตรวจ

  • การไฮไลต์คำในหน้า HR ต้องให้ API ส่งตำแหน่งคำที่ติดกฎมาด้วย (ตอนนี้มีในฝั่ง Admin) ถ้าไม่ต้องการเปิดเผยกฎ ให้แสดงแค่เหตุผล
  • ประวัติของประกาศต้องมี endpoint ประวัติสถานะของ Job

รายละเอียดผู้สมัคร (HR): สิ่งที่เปลี่ยน

โครงหน้า

  • ใช้โครงเดียวกับรายละเอียดใบสมัครฝั่งนักศึกษา: เส้นความคืบหน้า การ์ดดำของขั้นปัจจุบัน ประวัติด้านขวา ทั้งสองฝ่ายเห็นภาพเดียวกัน
  • การ์ดดำเปลี่ยนตามสถานะ: ส่งข้อเสนอ → ยืนยันเริ่มงาน → ความคืบหน้าการฝึก → ออกใบรับรอง

การกระทำ

  • การกระทำที่ทำย้อนกลับไม่ได้ (ยุติ, ถอนข้อเสนอ, เพิกถอนใบรับรอง) อยู่ในรายการ "ตัวเลือกอื่น" สีแดง ไม่วางข้างปุ่มหลัก
  • ฟอร์มที่ต้องกรอก (วันที่, เหตุผล) เปิดเป็นแผ่นในหน้า พร้อมคำเตือนผลที่ตามมา

ต้องตรวจ

  • คำเตือน "ฝึกจริงสั้นกว่า 30 วันจะไม่มีสิทธิ์รับ E-Certificate" ยังอยู่ในฟอร์มยุติ ตามข้อความเดิม

รับทราบดูข้อมูลนักศึกษา

รายงานปัญหา (อาจารย์): หน้าใหม่

โครงหน้า

  • แยกตามสถานะของรายงาน: เปิดอยู่ → รับทราบแล้ว → แก้ไขแล้ว (README §5.2)
  • แต่ละรายงานเป็นการ์ด: หัวข้อปัญหา ประเภท นักศึกษา บริษัท วันที่ และเนื้อหาเต็ม
  • ย้ำที่หัวหน้าว่าบริษัทมองไม่เห็นรายงาน

การดำเนินการ

  • ปุ่ม "รับทราบ" เปลี่ยนสถานะเป็น ACKNOWLEDGED
  • ทางไปต่อ (ติดตามบริษัท, ยุติการฝึก) อยู่ในหน้ารายละเอียดนักศึกษา เพราะการรายงานไม่เปลี่ยนสถานะใบสมัครเอง
